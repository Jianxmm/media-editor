适用于**直播分享、访谈对谈、多人分享、视频和播客**，也可以直接整理已有的转写初稿。保留讲述中的例子、细节和各人的观点，把需要回听确认的地方单独列清楚。长内容也会按段整理、对照原稿检查。

## 先让 AI 帮你安装

把下面这段话复制给你平时使用的 AI 助手，让它完成下载和安装：

```text
帮我安装“文稿整理”Skill：https://github.com/Jianxmm/media-editor
请使用最新版完整安装包；已装过的话，升级前先完整备份旧版。
```

安装完成后开启新对话，直接说“用文稿整理处理这份材料”。只装这一个，直播整理规则已经包含在里面。

## 发来材料，开始整理

把视频、音频、转写初稿或单条内容链接提供给助手，再说：

```text
用文稿整理处理这份材料，保留原意、重要细节和各人的发言。
给我整理稿和待核清单两个 Markdown 文档。
完成后，把两份文件的打开链接和保存位置发给我。
```

所有完整整理都保留论证、案例、限制和真实发言，直播与录播共用质量标准。需要供发布前审阅时，可以说：

```text
请完整整理这份内容，保留原有表达、案例、限制条件和真实问答，给我待发布成稿与待核清单。
```

直播回放和转写初稿都有时，一起提供。只有视频、只有文字，或者想整理播客，也可以先提供现有材料。[材料怎么给？](START_HERE.md#提供材料)

## 整理完，你会拿到两份文件

**① 整理稿**

理顺段落与标题，保留原话里的意思、案例和问答过程，供你审阅、修改。对话默认采用“姓名：正文”，不显示逐段时间；同一人已核实的连续发言可以分自然段，不反复署名。需要发布前审阅时，这份就是待发布成稿；该用途不要求素材必须是直播。

**② 待核对清单**

用表格逐项列出具体疑点、原句、正文实际写法、核对位置和状态。可以独立确认的问题分别记录结论；整场能力缺口集中说明。有可用的音频片段时附上链接，核对后的修改和依据也保留。

两份都是 **Markdown（`.md` 格式的文字文档）**，可以用笔记软件或文本编辑器打开。清单核对完、文稿审核后，再决定发布。

## 看看整理后的样子

下面节选自一段为演示编写的对谈，非真实直播记录。

**原转写**

> 主持人：你是怎么让自己坚持写下来的？
>
> 嘉宾：一开始我也做不到每天写啊。我就给自己定了个小要求，下班以后先坐下来写二十分钟，写得好不好先不管。

**整理后**

> **主持人：你是怎么让自己坚持写下来的？**
>
> **嘉宾：** 一开始我也做不到每天写。我就给自己定了个小要求：下班以后，先坐下来写二十分钟，写得好不好先不管。

保留第一人称和问答，让断句更顺。疑似错词另列清单，按原声核对。[看看完整对谈和待核清单 →](examples/整理前后.md)

## 其他材料，也可以这样用

| 你想整理什么 | 直接对助手说 |
| :--- | :--- |
| 视频、多人分享、播客 | “整理这段内容，保留重要案例和细节，给我完整稿和待核清单。” |
| 已有转写稿、字幕或其他文字 | “帮我整理这份文稿，保留原意，疑点单独列出来。” |
| 只想快速看重点 | “只要摘要。” |
| 想保留每句话 | “输出原始逐字稿，保留原语言、顺序和口头词。” |
| 想边读边回听 | “保留真实时间标记，方便回听。” |

视频可以提供本地文件，也可以提供 B站视频、小宇宙播客等**单条内容的链接**。链接无法读取时，改交本地文件。

时长、话题数量、互动和转写质量决定处理工作量；不设统一的长视频分钟数门槛。单人、对谈和多人使用相应方法，完整整理的质量要求一致。[统一标准](references/general.md) · [方法选择与完成条件](references/routing.md)

## 常见问题

<details>
<summary><strong>我用的 AI 工具没有 Skill 安装入口，怎么办？</strong></summary>

<br>

这套整理体系不绑定某一家 AI 产品。下载并解压后，让助手从 `SKILL.md` 开始，按任务读取引用的规则和模板。

涉及下载、转写和回听时，需要所用工具具备对应能力。日常使用直接说中文即可。[第一次使用](START_HERE.md)

</details>

<details>
<summary><strong>只有视频，或者只有文稿，可以整理吗？</strong></summary>

<br>

可以。只有音视频，先检查有没有字幕或可用的转写方式；只有文稿，就先整理文字，把需要原声确认的疑点留下。

只有文字也可完成有依据的文字编辑，无法回听的事项如实记录；主要事实、归属或输入覆盖存在大范围缺口时，说明具体未完成项。工具对输入的要求另行检查，不让素材迁就工具。

</details>

<details>
<summary><strong>长视频整理完，会不会只剩一份摘要？</strong></summary>

<br>

默认完整整理就会先通读全场，再逐段整理，最后对照原稿检查重要内容是否保留。主持人的追问、嘉宾的例子和讲述过程都在整理范围内；不会因为是普通视频就只给摘要或机器排版。

完整底稿和编辑记录会留在任务文件夹里，方便反查。

</details>

<details>
<summary><strong>多人分享、多人播客怎么整理？</strong></summary>

<br>

多人分享和播客可以按通用规则整理，依据已有的发言标记保留各人的观点。说话人不清楚时列入待核清单，不把不同人的话合在一起，也不猜身份。

单人讲述、双人对谈和多人互动按实际结构使用内部方法。已有可定位发言的多人转写与回放，可使用[多人核对模块](references/multi.md)；工具不自动识别无标签音频，受控测试不代表真实文稿质量已通过。

</details>

<details>
<summary><strong>常用名字总写错，或者任务中断了，怎么办？</strong></summary>

<br>

常用姓名、公司名和术语，可以告诉助手“帮我建立文稿整理词库，以后都用这一份”。有词库可作参考，具体原话仍按来源核对。

中途断了，就说“继续上次任务，使用原来的素材和任务目录”。更新版本时说“先完整备份旧版再升级”，词库和素材保存在安装目录外。[词库、继续任务与更新](references/maintenance.md)

</details>
