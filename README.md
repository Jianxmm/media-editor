## 这是什么，能帮你做什么

听完一场分享，想留下完整的内容；看到一段好视频，想整理成可读的文字；拿到自动转写，又得挨个处理错词、断句和说话人。

**文稿整理把这些步骤交给 AI 助手执行。** 你提供材料，说明用途，它按规则整理正文，把不确定的名字、数字和表达单独列出来。

| 你手上有什么 | 可以拿它做什么 |
| :--- | :--- |
| B站视频、小宇宙播客等单条链接 | 取得可用字幕或音轨，再整理内容 |
| 本机视频、录音 | 有原稿就用原稿，没有就先检查转写能力 |
| 字幕、转写稿、其他文字 | 直接整理，不必为了有视频而重复转写 |
| 单人直播分享、双人访谈的回放与原稿 | 按更严格的直播标准，保留讲述过程、真实问答与追问 |

它是装在 AI 助手里的 **Skill（一套整理规则和配套工具）**。需要支持 Skill、能读写文件的 AI 助手来执行；模型与转写服务由你使用的客户端或环境提供。

## 先看整理后的样子

默认得到两个 Markdown 文档，可以继续修改，也可以放进笔记软件阅读：

| 整理稿 | 待核清单 |
| :--- | :--- |
| 保留案例、数字、观点和限定条件，调整断句、段落与标题。 | 说明哪里拿不准、原句是什么、目前怎么写、到哪里核对。 |

**下面是一个虚构的短例子，只展示处理方式。**

原转写：

> 先做了两场免费讨论，第一场12个人，第二场18个人。人多不是说大家就愿意付费啊。后来99元的小课，8个人参加。平台好像叫云禾还是云合，这里没听清。

整理稿中的表达：

> 讲者先组织了两场免费讨论，分别有12人和18人参加。他强调，参与人数不能直接说明付费意愿。随后，他开设了一次99元的小课，共有8人参加。

待核清单中的一项：

| 原句 | 当前处理 | 怎样核对 |
| :--- | :--- | :--- |
| “云禾还是云合” | 暂未使用具体平台名称，保留待核项。 | 回听对应原声，或查已确认的官方资料；本例只有文字，没有回听链接。 |

**有依据才改成确定表达；只有猜测，就把疑点留下。** 有真实时间或已生成的音频片段时，清单附核对位置或链接。只有文字也能整理，但会注明无法核对原声。

## 安装只要发一句话

打开支持 Skill 的 AI 助手，把下面这句话发给它：

```text
帮我安装“文稿整理”Skill：https://github.com/Jianxmm/media-editor
请下载最新版完整安装包，确认当前客户端的技能目录后安装。
如果已安装，先检查版本；升级前完整备份旧版，保留我的词库和素材。
```

装好后，**开启新对话**。在本机 Codex 中，技能名称是「文稿整理」，调用名是 `$media-editor`。

**只装这一个。** 直播整理规则已经包含在包内，不用另外安装旧的直播 Skill，也不用在历史版本中挑选。

<details>
<summary><strong>如果助手不能直接从链接安装</strong></summary>

1. [下载最新版 media-editor.zip](https://github.com/Jianxmm/media-editor/releases/latest/download/media-editor.zip)。
2. 解压得到 `media-editor` 文件夹，保留隐藏目录和全部文件。
3. 把整个文件夹交给助手，说：“请读取 README.md 和 SKILL.md，帮我把这个 Skill 安装到当前客户端的技能目录。”

下载的是 Skill 资料包，不是需要双击运行的软件。[详细安装与排查 →](START_HERE.md)

</details>

## 装好以后这样用

### 整理普通视频、播客或文字

上传文件、拖入素材，或把具体文件路径／单集链接填进去：

```text
用文稿整理处理这份材料，给我完整阅读稿和待核清单两个 Markdown。
保留重要案例、数字、原意和限定条件。
材料：［文件路径、粘贴的原文，或单条视频／播客链接］
```

已有字幕或转写稿就一起提供。助手会先检查能否读取完整内容；平台打不开时，可以改交本地文件。**网页简介不能当作原稿，链接也不保证每个平台都能下载。**

### 按我们的直播标准整理

```text
请按直播标准整理这场直播，保留原话、真实问答和追问过程。
输出待发布文稿和待核对清单两个 Markdown。
回放：［视频路径］
原转写：［文稿路径］
```

这一条会调用**随包提供的原有直播整理核心**，按单人分享／双人访谈分别处理。完整流程的区别在这里：

| 关注什么 | 直播标准怎样处理 |
| :--- | :--- |
| 谁说的 | 用回放核验说话人，原转写标签只作线索。 |
| 有没有删掉重要内容 | 先通读全场、盘点内容，再整理，并从原稿反查覆盖情况。 |
| 有没有把对谈压成总结 | 保留真实问答、追问、例子和表达过程，避免过度压缩。 |
| 拿不准怎么办 | 定位原声核对；未解决的事项留在清单里，不假称已听清。 |

**交到你手上的两份主文件始终是「待发布文稿」和「待核对清单」，格式都是 Markdown。** 底稿、覆盖表和质检记录留在任务目录供追溯。

当前完整直播标准支持单人分享和双人访谈。缺少回放或必要核验依据时会说明缺口；三人及以上不按这套直播标准验收。待发布稿处理完待核事项并经过人工审核后，再由你决定发布。

### 只想要摘要、逐字稿或带时间的稿

不需要记模式名，直接说明你想得到什么：

| 你的需求 | 直接这样说 |
| :--- | :--- |
| 快速了解内容 | “只要摘要。” |
| 完整稿加摘要 | “整理成完整稿，开头加一段摘要。” |
| 尽量保留每句话 | “输出原始逐字稿，保留原语言、顺序和口头词。” |
| 方便回听 | “整理成带真实时间标记的稿件。” |
| 先保存素材 | “只获取这一条音频，暂不整理。” |

没有可靠时间信息时不会编造时间。明确要求直播标准时，两份直播主交付保留，其他形式作为补充。

## 越用越顺手的几件事

这些也可以直接让助手做：

| 你遇到的情况 | 对助手说 |
| :--- | :--- |
| 总有相同的人名、公司名被写错 | “帮我建立文稿整理词库；以后普通内容和直播共用这一份。” |
| 上次做到一半中断 | “继续上次任务，使用原来的素材和任务目录。” |
| 想更新版本 | “帮我升级文稿整理，先完整备份旧版。” |
| 升级后想换回去 | “使用上次升级返回的备份目录，恢复旧版。” |
| 想知道时间花在哪 | “记录本次处理阶段，完成后给我看实际耗时。” |

词库与素材放在安装目录外；已经确认的人名和术语可供整理与本地转写参考。来源、参数和文件校验一致时，工具会复用已完成的下载、转写与片段。真人核对时间没有测量，就如实留空。

## 开始之前，你可能还想知道

<details>
<summary><strong>需要会写代码吗？需要准备什么？</strong></summary>

日常使用可以用上面的自然语言指令。先准备一个支持 Skill、能读写文件的 AI 助手，以及你想整理的材料。

已有文字时，不需要安装音视频转写工具。下载、分离音轨或本地转写时，助手再按需检查 Python、FFmpeg、yt-dlp、whisper.cpp 等依赖。本地转写还需要模型文件。[素材与转写说明 →](references/acquisition.md)

</details>

<details>
<summary><strong>收费吗？我的材料会发到哪里？</strong></summary>

Skill 按 MIT 协议开源，安装包不含模型、账号或云额度。你使用的 AI 客户端、模型 API 或转写服务可能按各自规则计费。

使用云端模型时，交给模型处理的材料会发往相应服务；使用本地转写时，音频识别在本机执行。新增云服务、上传范围和费用按你的授权处理，不能把安装 Skill 当成上传或付费授权。Skill 本身不会自动发布稿件或给别人发送内容。

</details>

<details>
<summary><strong>Codex、WorkBuddy 都能用吗？效果一样吗？</strong></summary>

当前已验证本机 Codex 的安装与单一技能入口，音视频工具和短样例有实际检查。WorkBuddy、其他设备及真实长场质量仍待进一步验收。

相同规则有助于统一流程，但不同模型和工具的理解、转写和执行能力仍会影响结果；不承诺装上后所有客户端效果相同。[已验证范围与待办 →](VALIDATION.md)

</details>
