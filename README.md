## 一场两三个小时的直播，怎样整理

长直播里有故事、方法，也有追问、停顿和临时岔开的话题。直接看转写稿，往往断句混乱、错词不少；只留一份摘要，又容易丢掉那些让人真正听懂的例子和对话。

**文稿整理从长直播的编辑需求出发，重点面向 2–3 小时的单人分享和双人访谈。** 保留讲述与问答的展开过程，把原稿整理成便于阅读的正文，再把需要回听、查证的地方单独列出来。

| 整理时关注什么 | 具体怎样做 |
| :--- | :--- |
| 内容有没有遗漏 | 先通读全场，梳理主题、案例和问答，再逐段编辑，最后对照原稿检查。 |
| 话是谁说的 | 结合回放核验说话人，保留主持人与嘉宾各自的表达。 |
| 原话里的意思有没有变 | 保留数字、例子和限定条件，不把一段对话压成几句结论。 |
| 转写有错怎么办 | 有疑点就定位原声；暂时无法确定的内容放进待核清单，不靠猜测改成定论。 |
| 长内容中途没做完 | 保留任务记录和已完成部分，核对材料一致后继续处理。 |

这套体系也可以处理普通视频、播客和已有文字，不需要再安装另一个 Skill。

## 你会得到什么

**按直播标准整理时，交付两份主要的 Markdown 文档：**

| 待发布文稿 | 待核对清单 |
| :--- | :--- |
| 保留原意、重要细节和真实问答，整理好段落与标题，供你审阅、修改。 | 列出有疑问的原句、当前写法、需要确认什么，以及可用的回听位置或音频链接。 |

完整底稿、内容覆盖表和质检记录保留在任务目录里，需要时可以反查。待核事项处理完、经过人工审核，再决定发布。

普通内容默认也交付整理稿与待核清单。只想要摘要、逐字稿或带时间的稿件，可以直接说明。

## 先看整理后的样子

下例是为演示编写的对谈片段，非真实直播记录。

**原转写**

> 主持人：你是怎么让自己坚持写下来的？
>
> 嘉宾：一开始我也做不到每天写啊。我就给自己定了个小要求，下班以后先坐下来写二十分钟，写得好不好先不管。有时候就两三百字，但至少今天动笔了。
>
> 主持人：那写到一半卡住呢？
>
> 嘉宾：先放着呀。我会把卡住的那一段标出来，第二天再看。还有个办法，就是把初稿放到非书文档里，找一个朋友帮我看。他不一定帮我改，他就问一句，你这段到底想说什么，我经常就知道怎么改了。

**整理后的片段**

> **主持人：你是怎么让自己坚持写下来的？**
>
> **嘉宾：** 一开始我也做不到每天写。我就给自己定了个小要求：下班以后，先坐下来写二十分钟，写得好不好先不管。有时候只有两三百字，但至少今天动笔了。
>
> **主持人：那写到一半卡住呢？**
>
> **嘉宾：** 先放着。我会把卡住的那一段标出来，第二天再看。
>
> 还有个办法，就是把初稿放到文档里，找一个朋友帮我看。他不一定帮我改，就问一句：“你这段到底想说什么？”我经常就知道怎么改了。

**待核清单里留下这一项**

| 原句 | 当前处理 | 需要核对什么 |
| :--- | :--- | :--- |
| “把初稿放到非书文档里” | 暂写为“把初稿放到文档里”，保留协作方法。 | “非书”是否为“飞书”？需回听确认；本例没有原声，不直接改成确定名称。 |

保留第一人称和问答，理顺段落；错词的候选写法与已确认的原话分开记录。[查看两份完整示例 →](examples/整理前后.md)

## 安装与使用

这是一套开源的文稿整理规则和配套工具，**不绑定某一家 AI 产品**。支持 Skill 的工具可以直接安装；其他 AI 工具也可以读取 `SKILL.md` 及其引用的规则，作为整理任务的工作说明。涉及下载、转写和回听时，需要所用工具具备对应能力。

### 第一步：把这段话发给 AI 助手

```text
帮我安装“文稿整理”Skill：https://github.com/Jianxmm/media-editor
请下载最新版完整安装包，安装到当前工具的技能目录。
如果已安装，升级前完整备份旧版，保留我的词库和素材。
```

装好后开启新对话，直接说“用文稿整理处理这份材料”。直播规则已包含在包内，只需安装这一个 Skill。

<details>
<summary><strong>想手动下载，或者所用工具没有 Skill 安装入口？</strong></summary>

1. [下载最新版 media-editor.zip](https://github.com/Jianxmm/media-editor/releases/latest/download/media-editor.zip)。
2. 解压得到 `media-editor` 文件夹，保留隐藏目录和全部文件。
3. 有 Skill 安装入口时，把整个文件夹交给助手安装；没有时，让助手从 `SKILL.md` 开始，按本次任务读取引用的规则和模板。

不要只复制一个入口文件，直播规则、模板和工具也在包内。[详细步骤 →](START_HERE.md)

</details>

### 第二步：提供材料，说清用途

**整理直播，直接用这一段：**

```text
请按直播标准整理这场直播，保留原意、重要细节、真实问答和追问过程。
输出待发布文稿和待核对清单两个 Markdown。
回放：［视频路径］
原转写：［文稿路径］
```

已有转写初稿就和回放一起提供，不必重新转写整场。有疑点时再定位原声。暂时没有初稿，可以先检查可用的转写方式；缺少回放或必要核验材料时，说明还需补什么。

**整理普通视频、播客或文字，可以这样说：**

```text
用文稿整理处理这份材料，给我完整阅读稿和待核清单两个 Markdown。
保留重要案例、数字、原意和限定条件。
材料：［文件路径、原文，或单条视频／播客链接］
```

| 你手上有什么 | 怎样开始 |
| :--- | :--- |
| 直播回放与转写初稿 | 两份一起提供，按直播标准整理。 |
| 本机视频、录音 | 优先用已有原稿；没有原稿时先取得文字。 |
| B站视频、小宇宙播客等单条链接 | 读取可用字幕或取得音轨；链接无法读取时改交本地文件。 |
| 转写初稿、字幕或其他文字 | 直接整理；只有文字时，注明哪些疑点还需原声核对。 |

完整直播流程支持单人分享与双人访谈，三人及以上不按这套标准验收。网页简介不能代替原稿。

### 想换一种输出？直接说

| 想得到什么 | 可以这样说 |
| :--- | :--- |
| 摘要 | “只要摘要。” |
| 完整稿加摘要 | “整理成完整稿，开头加一段摘要。” |
| 原始逐字稿 | “保留原语言、顺序和口头词。” |
| 带时间的稿件 | “保留真实时间标记，方便回听。” |
| 只保存素材 | “只获取这一条音频，暂不整理。” |

明确要求直播标准时，待发布文稿和待核清单始终保留，其他形式作为补充。没有可靠时间信息时，不编造时间。

## 词库、续跑和更新

| 想做什么 | 对助手说 |
| :--- | :--- |
| 记住常用人名、公司名和术语 | “帮我建立文稿整理词库，以后普通内容和直播共用这一份。” |
| 接着上次的任务整理 | “继续上次任务，使用原来的素材和任务目录。” |
| 更新版本 | “帮我升级文稿整理，先完整备份旧版。” |
| 恢复旧版 | “使用上次升级返回的备份目录恢复。” |
| 查看耗时 | “记录本次处理阶段，完成后给我看实际耗时。” |

词库与素材保存在安装目录外。材料和参数一致时，复用已完成的下载、转写与音频片段；耗时按实际记录显示。[详细说明 →](references/maintenance.md)

## 使用前的两个问题

<details>
<summary><strong>需要会写代码吗？</strong></summary>

日常使用可以直接说中文。已有文字就先整理文字；下载、提取音轨或本地转写时，再让助手检查所需工具和模型。[素材与转写说明 →](references/acquisition.md)

</details>

<details>
<summary><strong>收费吗？材料会发到哪里？</strong></summary>

整理体系按 MIT 协议开源。你选择的 AI 工具、模型或转写服务可能另行计费，下载包不含账号和云额度。

使用云端模型时，提交的内容由相应服务处理；本地转写在本机识别音频。素材上传、付费及对外发送按你的授权执行，整理完成后由你决定如何使用稿件。

</details>
