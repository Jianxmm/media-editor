# 让待核清单方便核对

只改善已有疑点的呈现和定位，不新增完整性审计，不自动搬运转写核对包，也不降低原有 P0/P1 或终审条件。

主清单默认用便于扫描的表格：`级别 | 时间码 | 问题类型 | 原文/成稿 | 处理建议 | 状态`。开头简述待核数量和优先事项；每行写清具体疑点、当前采用的说法与下一步，不把同一段状态声明逐项重复。时间可点击定位原文或原声；长原句、多处位置、核对记录和技术过程放到链接详情或折叠附录，主表不堆完整记录。用户指定其他呈现方式时遵从。

P0/P1先列，P2后列。**一项对应一个能独立确认的疑点**：人名、任职年份和一处插话若可分别得到结论，就分别列项，保留同一父问题编号的联系；同一数量及其单位、不能拆开的完整意思仍在一起。由编辑判断，不机械按标点拆分。每项保留稳定编号，不能因为位置相同就合并状态。

“原文”引用可定位的实际短句，保留否定、数字、单位与限定；不能只写“名称有疑问”。“成稿”引用正文实际采用的一句或短语，不只写“已保守处理”。长上下文放详情，不能用摘要替代核对所需的关键原话。整场听辨能力或人声边界缺口集中列在“整场核验条件”，不在每一行重复，也不替代局部事实问题；本地转写接缝分别记录位置与结论。

收到真实核对反馈后，先修正文及必要的相邻上下文，再更新对应问题的结论、方法、核对人、日期与证据入口。未确认的事项维持待确认；保守改写或删除是编辑处理，不等于已听清。已确认结论仍回到原任务记录，不能把一个问题的结论借给其他问题，也不由清单生成器判断可发布。

不把所有技术提示都写成已证实的错误。分段切点写“需检查衔接”；时间空白写“需确认是静音、音乐还是未识别语音”。原文没有时间则用段落/行号，不编造时间。没有音频时说明核对条件，不能给失效链接。

需要重复生成时可让助手准备 JSON 并运行：

```text
python <SKILL_ROOT>/scripts/workspace_tools.py review <问题记录.json> --output <新的待核清单.md>
```

输入形状：

```json
{"issues":[{"id":"Q03-名称","priority":"P1","location":"00:30","original":"原始转写中的具体短句","question":"这里说的是哪个名称？","draft":"正文实际采用的一句","action":"回听该句并核对名称","source_link":"原文索引.md#s0018","clip":"回听/名称.wav","status":"待确认"}]}
```

`source_link`和`clip`可省略；提供本机链接时文件必须存在，原文锚点须有效。没有时间码使用原稿段落或行号。`scope`默认为`local`，整场能力缺口用`global`；它不改变优先级或发布影响。旧输入不含编号和状态时仍可生成，默认待确认。用户无需维护JSON，助手根据自然语言反馈处理。

已处理项保留`finding`具体结论和`review`核对记录：`method`、`reviewer`、`checked_at`、`evidence`（证据路径或资料链接数组）。支持的状态与方法：

| 状态 | 记录方法 | 含义 |
| --- | --- | --- |
| 待确认／待核 | 不代填核听结论 | 仍需处理 |
| 已回听 | 真人回听／音频理解 | 仅在确有真实核听记录时采用；ASR不是该方法 |
| 已资料核对 | 资料核对／回放画面 | 仅确认资料或画面所支持的事项，不自动确认人声和原词 |
| 已保守表达 | 保守改写 | `draft`必须能在提供的正文证据文件中找到，原声仍可能未核 |
| 已删除 | 删除 | 记录删除内容、理由和对应稿件，不冒称原话已确认 |

生成器检查字段、文件与锚点，不验证“确实听过”或核对结论本身。助手只录入真实完成的动作；程序接受记录不代表发布审计通过。新清单另存，程序拒绝覆盖不同内容的人工清单。

直播模式继续保留核心清单模板、状态字段、台账、索引和回听记录；不要用通用渲染器直接覆盖核心必需产物或让旧检查失效。两份主要交付仍为待发布文稿与待核清单。
