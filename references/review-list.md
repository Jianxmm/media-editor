# 让待核清单方便核对

只改善已有疑点的呈现和定位，不新增完整性审计，不自动搬运转写核对包，也不降低原有 P0/P1 或终审条件。

清单开头说明有多少问题、几个原文位置和先看哪些。每个位置列原句，再列疑点、当前稿采用的写法、建议核对方法和可用原声链接。P0/P1 先列，P2 后列；同一位置归组，独立问题逐项保留，不因合并排版丢掉事实。已确认结论仍回到原任务记录，排版工具不能代替真人确认。

不把所有技术提示都写成已证实的错误。分段切点写“需检查衔接”；时间空白写“需确认是静音、音乐还是未识别语音”。原文没有时间则用段落/行号，不编造时间。没有音频时说明核对条件，不能给失效链接。

需要重复生成时可让助手准备 JSON 并运行：

```text
python <SKILL_ROOT>/scripts/workspace_tools.py review <问题记录.json> --output <新的待核清单.md>
```

输入形状：

```json
{"issues":[{"priority":"P1","location":"00:30","original":"虚构原句中的不确定名称","question":"请确认名称写法","draft":"正文暂采用不含名称的表达","action":"回听原声或查已确认物料","clip":"相对于问题记录的音频文件.wav"}]}
```

clip 可省略；提供时必须存在。程序按原级别和精确位置归组，生成链接并拒绝覆盖不同内容。用户无需维护 JSON，助手负责处理。

直播模式继续保留核心清单模板、状态字段、台账、索引和回听记录；不要用通用渲染器直接覆盖核心必需产物或让旧检查失效。两份主要交付仍为待发布文稿与待核清单。
