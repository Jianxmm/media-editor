# 任务入口与方法选择

## 先确定用户要的产物

默认是完整整理稿与待核清单，不要求用户先选“普通视频标准”或“直播标准”。明确只要摘要、逐字稿、时间稿或下载时按要求处理；发布前审阅是使用场景，不自动改变编辑质量。

判断使用当前请求与素材，后续纠正优先于早先模板。用户说“按直播标准”通常表示完整忠实、保留现场；采用同一质量标准。明确指定某个既有工具、审计包或历史产品格式时，同时保留该明确要求。

## 再按内容特点选方法

这些方法可以同时启用，不把素材划成不同质量等级：

| 实际内容特点 | 相应方法 |
| --- | --- |
| 单人讲述、演讲、课程 | 保留原推进顺序、步骤、论证、案例和必要互动；无需虚构问答。 |
| 访谈、圆桌、会议问答、对话播客 | 保留提问前提、回答、追问、回应、分歧与例子；不把多轮对话压成观点合集。 |
| 多人轮流分享或交叉讨论 | 建立稳定人物和边界，逐人记录归属；保留少数意见和相互承接。 |
| 调试、重复促销、摆位、截图和关播 | 按是否推进主题、人物或关系决定删留，记录有实质影响的删减；不凭“直播尾声”一律删除有效内容。 |
| 内容较多、话题多、转写分段或信息密集 | 分段处理，覆盖全场和每个话题，核查接缝及末尾；按实际复杂度安排工作量。 |
| 术语、数字、否定、限制或发言归属不清 | 定位原文与回放核对；无法确认的保守处理并保留问题，不新增确定性。 |

不设统一的“20分钟以上就是长视频”门槛，也不用时长决定是否完整整理。用户要求测试素材至少20分钟，只是该次选材条件。录制还是直播、平台名称、标题有无“圆桌”、表面标签数都不能证明真实说话人数。

## 证据与工具怎么选择

先记录实际输入和能力：是否有全片、原始转写、时间定位、可靠换人边界、身份线索，以及能否实际理解音频或核对画面。能播放、截取或转写不等于能听辨。缺少听辨能力时，开始就说明受影响范围及需要补充的真实核听结论或可信逐段人声记录，同时继续有依据的文字编辑与来源反查；不能到最后才以“全场待核”代替说明，也不因此自行上传新服务。不要先挑一个工具，再让素材和结论迁就它。

- 使用中性称谓前，先核查可访问的本场片头、姓名字幕、人物介绍、发布者说明，必要时查看同场署名材料，主动建立有依据的人物对应；不能只凭名单顺序猜座次。查证后实名仍未知、但边界可靠，才用稳定中性称谓并说明缺少什么证据。
- 人物姓名与逐段归属分别判断：姓名已确认不代表所有插话已认人；某处归属不清也不使已确认的姓名重新变成未知。已核实的发言直接署名，只在受影响段落保留待核，不把局部疑点泛化到全稿。
- 标签或换人有局部冲突：先核对对应原声，不将全文一概停在转写阶段。
- 整场边界不明：不能把多人语句拼在“回应/补充”名下形成貌似可靠的完整对话。可保留局部编辑，但如实报告全场归属未完成。
- 只有文字：可以完成有依据的文字编辑和来源反查；原声准确性不能被证明，按影响范围报告。
- 使用单人、双人或多人工具：遵守各自输入、来源绑定与审计合同。未标注 SRT 不被某工具接受，说明该工具无法直接处理它，既不能证明文字没价值，也不能证明归属问题已经解决。

原核心的五位置核验、声音时间轴、逐块冲突、覆盖与决策记录都是实现质量要求的办法。根据实际问题及所用模块使用；已选模块的必需检查不能绕过。旧核心的一人/两人假设不扩用于多人。具体人物、数值、保留比例及包装依各自适用条件，不从一个标杆强套所有内容。

## 怎样判断交付完成

完整整理的共同验收见 [统一标准](general.md)。两份主交付始终是编辑成稿和待核清单；内部保留能够反查的来源、覆盖、取舍和质检证据。

| 实际状态 | 报告与动作 |
| --- | --- |
| 只有 ASR/字幕排版，还没有完成编辑 | 转写完成，继续整理；不把机器阅读候选当作成稿。 |
| 全场编辑和来源反查完成，主要内容及归属可靠，仅有局部待核 | 交付成稿与定位明确的清单，说明剩余事项；不因尚未人工终审否定已完成的编辑。 |
| 大范围缺段、主要事实或整场归属不可靠 | 列明已完成部分和具体失败项、已试路径、最小补充条件，不宣称完整成稿完成。 |
| 实际完成真人终审且获授权发布 | 按真实结论与授权处理；不从文件名、格式或机器通过推定。 |

测试时先冻结输入和标准，再跑内容、工具和完成状态检查。发现问题记录后再做范围明确的修复，不为得到通过而临时删门槛。规则变更后重新测试的结果另存，不覆盖前次现场，也不追认旧稿合格。
